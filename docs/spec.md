# DanceAI — спецификация

> Только принятые решения о том, что делает приложение, и план. Обсуждения, история и исследования — вне репозитория. Файл обновляется отдельной задачей.
> Версия 1.2 — 14.11.2026.

## 1. Назначение
Танцор загружает видео танца своей пары. ИИ оценивает танец, называет ошибки и говорит, над чем работать. Цель — оценить свой танец, прогресс и результат без тренера.

## 2. Пользователи
- Студенты 18+, категории Хобби-4 и Хобби-6 (≈ Н-класс).
- Пользователь — сам танцор. Только пары, соло не поддерживается.
- Язык интерфейса — только русский.

## 3. Танцы (MVP)
Медленный вальс, квикстеп, ча-ча-ча, самба (`slow_waltz`, `quickstep`, `cha_cha`, `samba` — как в `assets/criteria.json`). Танец выбирает пользователь, автоопределения нет.

## 4. Вход: видео
- Любые видео: тренировки и турниры. Жёстких ограничений длины, формата и ориентации нет.
- Звук (музыка) обязателен.
- Оценивается пара, которая большую часть времени в кадре и/или с которой начинается запись. Неоднозначное видео — ответственность пользователя.
- В приложении — краткая инструкция по съёмке: чем ближе и лучше видна пара, тем точнее оценка; должно быть очевидно, какую пару оценивать.
- Если `video_assessment.status` ≠ `ok` — до показа отчёта предупреждение с причинами (`issues`) и выбор: «Показать оценку всё равно» или «Загрузить другое видео».

## 5. Критерии
- Источник — `assets/criteria.json`: 4 компонента, общие критерии (все танцы), критерии и фигуры каждого танца.
- Критерии из файла — обязательный минимум: ИИ даёт вердикт по каждому. Остальное ИИ может отмечать на своё усмотрение (`additional_observations`).
- `per_person: true` — вердикт отдельно для партнёра и партнёрши плюс общий для пары; `false` — только для пары.
- Фигуры: ИИ распознаёт, называет и оценивает фигуры из списка; фигуры не из списка тоже называет (`figure_id: null`).
- Компоненты (по мотивам WDSF), шкала 1–10: Техника, Музыка, Партнёрство, Хореография и подача.

## 6. Выход: отчёт
- Формат — `assets/report.schema.json`, одинаковый для всех провайдеров и режимов. Пример — `test/fixtures/report_example.json`.
- Оценки: по каждому компоненту — пара (всегда) и, где применимо, партнёр и партнёрша (целые 1–10).
- **Общая оценка** = среднее четырёх оценок пары по компонентам, округлённое до 0,1. Считает приложение.
- Визуализация — радар-диаграмма по 4 компонентам: пара; партнёр и партнёрша — дополнительными линиями, если их оценки есть.
- Текст: сильные и слабые стороны отдельно партнёра, партнёрши и пары; общий вывод.
- Два уровня отчёта:
  - **Краткий**: общая оценка, 4 компонента, радар, до 3 первых ошибок с `severity: critical` (если их нет — первые 3 ошибки), «Над чем работать» (`priorities`).
  - **Подробный**: всё из краткого + все ошибки + вердикт по каждому критерию + распознанные фигуры с оценкой исполнения + разбор по людям + дополнительные наблюдения.
- Тон один: сухой, фактический.
- Отображение значений: `good` — «выполняется», `partial` — «частично», `poor` — «не выполняется», `not_visible` — «не видно»; `critical` / `major` / `minor` — «грубая» / «заметная» / «мелкая»; `leader` / `follower` / `couple` — «партнёр» / «партнёрша» / «пара».
- Не в MVP: таймкоды ошибок как отдельные элементы интерфейса, скелет и пометки на кадрах, упражнения «как исправить», выбор тона.

## 7. ИИ
### 7.1 Режимы
- Режим 1 — внешний ИИ по API (MVP; Android и Windows).
- Режим 2 — своя локальная модель (только Windows, после MVP; отдельный локальный процесс). Возвращает тот же отчёт.
- Выбор режима — в настройках; в MVP доступен только режим 1.

### 7.2 Провайдеры (режим 1)
- **Провайдеры равноправны, приоритета нет.** Приложение должно одинаково работать с разными ИИ. Логика, завязанная на конкретного провайдера, живёт только в его адаптере.
- Список провайдеров — данные в `assets/providers.json`; в интерфейсе — по алфавиту, плюс вариант «Свой (OpenAI-совместимый API)» с полями «Адрес API», «Модель», «Ключ API».
- Пользователь выбирает провайдера, вводит модель (текстом) и свой API-ключ.
- Адаптеры по типу API (`api_type`): `anthropic`, `google`, `openai`, `openai_compatible` (OpenRouter и «Свой»). Общий интерфейс: «материал + промпт → текст ответа».
- Для каждого провайдера в приложении: ссылка и пошаговая инструкция, как получить ключ (`key_steps_ru`), короткая заметка о тарифе (`free_note_ru`).
- Рекомендуемые модели (`recommended_models`) пока пусты — заполняются по итогам проверки на эталонном наборе. Если список пуст, блок не показывается.
- `verified_live: false` в `providers.json` — адаптер проверен только по документации и тестам на записанных ответах; в настройках пометка «не проверено вживую». Ставим `true` только по итогам живой проверки.
- Подсказка о модели под полем «Модель»: OpenRouter и «Свой» — `GET /models` (`architecture.input_modalities`, если есть): «Модель принимает: изображения, видео, звук» и кнопка включить видео; Google, Anthropic, OpenAI — «Модель найдена» / «Модель не найдена» (Google не сообщает модальности). Нет сети или метода — ничего не показываем. Ручной переключатель видео — главный.
- Лимиты бесплатных тарифов не хардкодить.
- VPN — забота пользователя, приложение это не решает.

### 7.3 Два способа подачи (зависит от модели, а не от провайдера)
- **Кадры + анализ музыки** — по умолчанию, работает с любой моделью, принимающей изображения: кадры с повышенной частотой; перед каждым кадром текстовая метка времени `t=12.50`; текст локального анализа музыки.
- **Видео целиком** — если модель принимает видео со звуком. Включается в настройках переключателем «Модель принимает видео со звуком» (по умолчанию выключен). Если адаптер провайдера не умеет передавать видео, переключатель недоступен (сейчас видео умеют `google` и `openai_compatible`).
  - Исходник целиком не отправляется: FFmpeg делает **облегчённую копию** во временной папке анализа — короткая сторона 480 px, 15 кадр/с, ~500 кбит/с, звук AAC моно 64 кбит/с, mp4. Кодек: аппаратный H.264 системы (`h264_mediacodec` на Android, `h264_mf` на Windows), запасной — встроенный MPEG-4 Part 2 (`mpeg4`; в сборке FFmpeg без GPL нет libx264). Копия удаляется вместе с остальными временными файлами при любом исходе. Кадры не извлекаются; анализ музыки — как всегда.
  - Предел размера копии — параметр адаптера (`maxVideoBytes`): `openai_compatible` — 20 МБ (у OpenRouter предел не документирован); `google` — без предела: до 14 МБ inline, больше — через File API (загрузка → ожидание обработки → ссылка в запросе → файл удаляется с сервера после анализа, при ошибке и отмене).
  - Копия больше предела, сервер ответил «слишком большой запрос» (413) или копию сделать не удалось — сообщение и кнопка **«Отправить кадрами»**: тот же анализ кадрами, без повторного выбора видео.
  - Частота, с которой модель смотрит видео, — параметр «Для разработчика» (1 / 2 / 4 кадр/с, по умолчанию 2), передаётся, где API это позволяет (Gemini `videoMetadata.fps`).
  - OpenRouter требует баланс от $1 для видео даже на бесплатных моделях (HTTP 402) — сообщение и кнопка «Отправить кадрами».
  - Отдельная звуковая дорожка (`input_audio`) не отправляется. Её добавим только если проверка покажет, что модель не слышит звук внутри видео, и только моделям с `audio` в `input_modalities`.
- Локальный анализ музыки передаётся в обоих способах.
- Частота и лимит числа кадров — параметры адаптера (у моделей разные лимиты на число изображений): по умолчанию 2 кадр/с и до 120 кадров; `anthropic` — до 100 (лимит API для моделей с окном 200k).
- **«Максимум кадров»** — поле в настройках провайдера рядом с моделью (и для «Своего»): пусто — по умолчанию адаптера. Нужно для моделей, которые отклоняют запрос с большим числом изображений (живая проверка: `nvidia/nemotron-3.5-super-vl:free` — 422 «content safety screening» уже на 20 кадрах, 10 проходят).

### 7.4 Подготовка видео (на устройстве)
1. Проверить, что файл читается и в нём есть звуковая дорожка. Нет звука — сообщение «В видео нет звука. Для оценки нужна музыка» и возврат к выбору видео.
2. Получить длительность.
3. Извлечь кадры с заданной частотой (параметр адаптера), уменьшенные по длинной стороне (параметр, стартово 768 px), с метками времени.
4. Извлечь звук и сделать анализ музыки: темп (BPM), размер и ожидаемый темп танца — из `criteria.json` (`music.meter`, `music.tempo_mpm`; темп — подсказка, не жёсткое ограничение), начала тактов и доли с таймкодами → текст по формату 7.6.
5. Всё временное (кадры, аудио, копии видео) — во временной папке приложения, удаляется сразу после анализа, в том числе при ошибке и отмене.
6. Работа — вне UI-потока, с прогрессом и возможностью отмены.

### 7.5 Промпт
Шаблоны в `assets/prompts/`:
- `analysis_system.md` — системный промпт (без плейсхолдеров);
- `analysis_user.md` — запрос;
- `input_video.md` / `input_frames.md` — описание материала, подставляется в `{{input_description}}`.

| Плейсхолдер | Файл | Что подставляется |
|---|---|---|
| `{{dance_id}}`, `{{dance_name_ru}}`, `{{dance_name_en}}` | analysis_user | из `criteria.json` |
| `{{input_description}}` | analysis_user | текст `input_video.md` или `input_frames.md` |
| `{{music_analysis}}` | analysis_user | текст по формату 7.6 |
| `{{components}}` | analysis_user | строка на компонент: `id — Название: описание` |
| `{{criteria}}` | analysis_user | общие критерии + критерии танца, строка на критерий: `id — Название [компонент: id; отдельно партнёр и партнёрша: да/нет]` |
| `{{figures}}` | analysis_user | строка на фигуру: `id — Русское название (English name) — примечание`; англ. название и примечание — только если есть |
| `{{report_schema}}` | analysis_user | содержимое `report.schema.json` |
| `{{duration_sec}}` | input_video, input_frames | длительность видео, с |
| `{{frame_count}}`, `{{fps}}` | input_frames | число кадров и частота |

Строгий структурированный вывод по схеме на стороне провайдера в общем случае **не включается** (наша схема может не пройти их ограничения): только режим «ответ — JSON», где API его поддерживает (OpenAI-совместимый `response_format: json_object`, OpenAI `text.format: json_object`; у Anthropic такого режима нет). Исключение — `google`: `responseMimeType: application/json` + `responseJsonSchema` — **упрощённая** схема, которую адаптер строит из нашей: только типы, обязательные поля и вложенность (`type`, `properties`, `required`, `items`, `$ref`/`$defs`), без перечислений, границ, форматов, описаний и `additionalProperties` (полную Google отклоняет — 400 «too many states for serving»), без `$schema` и `$id` (с `$id` Google не находит ссылки `$ref` на `$defs` — 400 «reference to undefined schema»). Не принял (400 про схему) — один повтор без неё, и до конца сеанса приложения эта модель получает запросы без схемы. Схема передаётся и в тексте запроса (`{{report_schema}}`), полная проверка — в приложении (7.7).

### 7.6 Формат анализа музыки
```
Темп: 87 BPM (29 тактов/мин), размер 3/4.
Начала тактов, с: 0.42, 2.49, 4.56, …
Доли, с: 0.42, 1.11, 1.80, …
Уверенность анализа: высокая.
```
Уверенность: `высокая`, `средняя` или `низкая — темп и доли могут быть неточными`. При сомнении анализ выдаётся с низкой уверенностью; строка `Анализ музыки недоступен.` — только если ритма в записи нет (или запись короче 8 с).

### 7.7 Обработка ответа
1. Убрать возможную обёртку ```` ```json ````, распарсить JSON.
2. Проверить по `report.schema.json` и по `criteria.json`:
   - `dance_id` совпадает с запрошенным;
   - `criteria_results` содержит каждый критерий танца (общие + специфичные) ровно один раз, лишних нет;
   - у критериев с `per_person: false` — `leader` и `follower` равны `null`; с `per_person: true` — не `null`;
   - `figure_id` и `criterion_id` (в фигурах и ошибках) — `null` или существующие id этого танца.
3. При ошибке проверки — один повторный запрос с описанием ошибки. Снова ошибка — понятное сообщение пользователю.
4. Ошибки API — понятное сообщение на русском, без ключа в тексте:
   - 401/403 — неверный ключ (403 с модерацией — «запрос отклонён провайдером»); 402 и исчерпанный баланс — «нет средств на счёте»;
   - 429 — лимит запросов: если сервер прислал `Retry-After` — «повторить можно через N»; у бесплатных моделей (`:free`) — подсказка про дневной лимит; автоматических повторов нет;
   - 404, неизвестная модель, модель не принимает изображения/видео — «модель недоступна»;
   - 413 и «слишком большой запрос» — «слишком большой объём» (в режиме видео — с кнопкой «Отправить кадрами»);
   - 5xx — ошибка провайдера; нет сети и таймаут — «нет связи с ИИ».
5. Ответ в обёртке ```` ```json ```` или с текстом вокруг — адаптер вырезает JSON до проверки (это не ошибка). Модель не приняла JSON-режим или лимит ответа (400 на этот параметр) — один повтор без него.
6. **Потолок времени — 5 минут на весь анализ вместе с повтором** (константа `analysisTimeLimit`). Повтор после невалидного ответа запускается, только если до потолка остаётся не меньше минуты и не меньше, чем занял первый запрос; иначе — ошибка «ИИ отвечает слишком долго» с кнопкой «Попробовать ещё раз». На экране анализа и в строке перед отправкой — «Анализ может занять до 5 минут». Таймауты транспорта: подключение 30 с; отправка — обрыв, если 60 с нет продвижения; ожидание ответа — не дольше потолка. Лимит ответа — 32000 токенов (с учётом «размышления»); у `anthropic` — 16000 (запрос без потоковой отдачи). Отмена обрывает HTTP-запрос сразу, удаляет временные файлы и загруженный в Google файл.
7. Прогресс на экране анализа: «Сжатие видео» (режим видео), «Отправка» с процентом, «Обработка видео у провайдера» (File API), «Анализ» — пока ждём ответ; при потоковой отдаче (`google`: `streamGenerateContent?alt=sse` — без потока сервер закрывал соединение примерно через 240 с) — «ИИ пишет отчёт · N КБ».

### 7.8 Демо-режим и «Для разработчика»
- `StubAiProvider` (заглушка) реализует тот же интерфейс, что и адаптеры. Включается переключателем **«Демо-режим (без ИИ)»** в «Для разработчика» — чтобы проверять интерфейс без ключа и без расхода лимитов. На экране анализа — пометка «Демо-режим: без ИИ».
- Заглушка ждёт 3–5 с и возвращает **текст** JSON-отчёта для выбранного танца, сгенерированный по `criteria.json` (все критерии, несколько фигур, 10–15 ошибок, оценки). Ответ проходит ту же обработку, что и настоящий (7.7). Сценарии: «Нормальный ответ», `low_confidence`, `unusable`, «Нет части личных оценок», «Невалидный JSON», «Неверный ключ», «Лимит запросов», «Нет сети».
- Подготовка видео (7.4) и сборка промпта (7.5) работают по-настоящему и в демо-режиме.
- «Для разработчика» по последнему анализу: подготовка видео (размер, кадры или облегчённая копия с кодеком, звук, темп, время этапов, превью кадров), провайдер, модель, способ подачи (и частота для видео), по каждому запросу — отправлено байт, время отправки и до ответа, токены (если API их возвращает), причина завершения, был ли повтор; собранный промпт, анализ музыки, сырые ответы и ошибки проверки. Частота кадров видеорежима — 1 / 2 / 4 кадр/с. Уровень размышления (где API позволяет; Gemini `thinkingConfig.thinkingLevel`): по умолчанию модели / low / medium / high.
- **«Сохранить JSON»** — файл `danceai_<танец>_<модель>_<ГГГГММДД-ЧЧММСС>.json`: версия приложения и `criteria.json`, уровень размышления и «Максимум кадров», SHA-256 шаблонов промпта, `criteria.json` и схемы, параметры подачи (кадры: число, частота; видео: размер, разрешение, кодек, частота для модели), текст и параметры анализа музыки, время этапов, запросы, итоговый отчёт, сырые ответы. Без ключа, без промпта и картинок. Android — системный диалог «Сохранить как», Windows — диалог сохранения. Нужно для проверки на эталонном наборе (шаг 7).
## 8. Приватность
- Видео и производные (кадры, аудио) удаляются сразу после анализа, в приложении не хранятся.
- Без регистрации и входа. История оценок не хранится.
- Публичного обмена видео нет.
- API-ключ хранится только на устройстве, в защищённом хранилище ОС; не попадает в логи и тексты ошибок.
- Перед отправкой — строка: «Видео отправляется выбранному ИИ-провайдеру. На бесплатных тарифах провайдер может использовать данные».

## 8а. Дизайн
- Одна тема — тёмная «сцена»: тёмный фон, мягкие прожекторные градиенты и свечение, яркие акценты; Стандарт и Латина — разные акцентные цвета.
- Анимации — сильная сторона: переходы между экранами, появление карточек, «живой» экран ожидания анализа, анимированная радар-диаграмма, счётчики оценок.
- Шрифты — с кириллицей, встроены в приложение (без загрузки из сети).
- Адаптивная вёрстка: телефон (портрет) и окно Windows (широкое — в две колонки там, где уместно).
- 60 fps без подвисаний; анимации не мешают работе (можно пропустить, не задерживают навигацию).

## 8б. Экраны
1. **Главный** — выбор танца: 4 карточки (группы «Стандарт» и «Латина»), вход в настройки и в инструкцию по съёмке.
2. **Видео** — выбор файла, превью (если доступно на платформе), длительность, строка о приватности, кнопка «Оценить». Если ИИ не настроен — подсказка открыть настройки; в демо-режиме — пометка, что оценка без ИИ.
3. **Анализ** — этапы: проверка видео → кадры (или сжатие видео) → музыка → отправка (с процентом) → [обработка видео у провайдера] → анализ → проверка ответа; прогресс, отмена.
4. **Предупреждение** при `status` ≠ `ok` (раздел 4).
5. **Краткий отчёт** и **Подробный отчёт** (раздел 6).
6. **Ошибка** — понятный текст и действие: «Повторить», «Выбрать другое видео», «Открыть настройки», «Отправить кадрами» (после ошибки режима видео).
7. **Настройки** — режим ИИ («Внешний ИИ по API»; «Своя модель» — неактивно, «скоро», только Windows), провайдер, модель, адрес API (для «Своего»), ключ (скрыт, с показом по кнопке), подсказка о модели (и текст `model_hint_ru` из `providers.json`, у Google — «Проверена модель gemini-3.6-flash. У gemini-3.8-flash на бесплатном тарифе очень маленький лимит запросов.»), «Максимум кадров» (7.3), пометка «не проверено вживую» (7.2), переключатель «Модель принимает видео со звуком», «Как получить ключ», раздел «Для разработчика» (7.8), «Лицензии».
8. **Инструкция по съёмке** и **Как получить ключ** (по провайдеру, из `providers.json`).

## 9. Платформы и распространение
- Android (APK) и Windows из одного Flutter-кода.
- Распространение — автором напрямую и через GitHub (APK и сборка для Windows), без магазинов приложений.
- На GitHub выкладываются два APK: полный (все архитектуры) и arm64-v8a.
- Приложение бесплатное.
- Лицензия кода — все права защищены (`LICENSE`): код открыт на GitHub только для ознакомления; использование, копирование, изменение и распространение — с письменного разрешения автора. Не MIT/GPL. Сторонние компоненты — по своим лицензиям (экран «Лицензии»); права по LGPL (FFmpeg, FFmpegKit) — изменение и замена библиотек — не ограничиваются.
