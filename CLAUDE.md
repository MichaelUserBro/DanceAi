# DanceAI — инструкции для агента

## Что за проект
DanceAI — приложение для бальных танцоров (студенческая лига, категории Хобби-4 / Хобби-6). Пользователь выбирает танец и загружает видео своей пары со звуком; ИИ оценивает танец по заданным критериям и возвращает отчёт: оценки по 4 компонентам, сильные и слабые стороны, ошибки партнёра, партнёрши и пары, над чем работать. Что именно делает приложение — `docs/spec.md`.

## Стек и версии
- Flutter 3.50.0 (stable), Dart 3.14.0.
- Платформы: **Android** (Android SDK 37) и **Windows** (Visual Studio 2022, C++). Web, iOS, macOS, Linux не поддерживаются.
- Material — отдельный пакет `material_ui` (с Flutter 3.47 Material вынесен из SDK). Импорт: `package:material_ui/material_ui.dart`, НЕ `package:flutter/material.dart`. Зависимость `material_ui` в pubspec.yaml — штатная, не удалять.
- Пакет `dance_ai`, org `com.danceai`.
- Репозиторий: https://github.com/MichaelUserBro/DanceAi, ветка `main`.

## Файлы-источники (читать перед задачей)
- `docs/spec.md` — что делает приложение (только принятые решения) и план с текущим шагом.
- `assets/criteria.json` — компоненты оценки, критерии и фигуры по танцам. Критерии в коде не хардкодятся — только отсюда.
- `assets/providers.json` — список провайдеров ИИ (равноправных), ссылки и инструкции по ключам.
- `assets/report.schema.json` — JSON-схема отчёта ИИ. Единый формат для всех провайдеров и режимов.
- `assets/prompts/` — шаблоны промпта анализа; `{{плейсхолдеры}}` подставляет приложение (таблица — в `docs/spec.md`, раздел 7.5).
- `test/fixtures/report_example.json` — пример валидного отчёта (для тестов и вёрстки экранов).

## Архитектурные правила
1. Каждый провайдер ИИ — **адаптер** с общим интерфейсом. Провайдеры **равноправны**: никаких приоритетов и логики под конкретного провайдера вне его адаптера. Интерфейс приложения не знает, какой провайдер работает. Способ подачи (кадры или видео) зависит от возможностей модели, а не от провайдера.
2. Любой ответ ИИ приводится к `assets/report.schema.json` и проверяется (схема + id критериев и фигур из `criteria.json`). Невалидный ответ — понятное сообщение пользователю, а не падение.
3. Адаптеры — `lib/analysis/providers/` (общая база `HttpAiProvider`, транспорт `HttpTransport` на dart:io). Заглушка `StubAiProvider` — только «Демо-режим (без ИИ)» в «Для разработчика» (`docs/spec.md`, 7.8).
4. Общую оценку считает приложение, а не ИИ (правило — в `docs/spec.md`).
5. **Видео не хранится**: временные файлы (видео, кадры, аудио) удаляются сразу после анализа — и при успехе, и при ошибке.
6. **API-ключ** пользователя хранится в защищённом хранилище ОС и никогда не попадает в код, репозиторий, логи, тексты ошибок и исключений.
7. Интерфейс — только на русском. Идентификаторы в коде и ключи JSON — на английском.
8. Нет регистрации, сервера и истории оценок.
9. Приложение должно «летать»: тяжёлая работа (видео, кадры, анализ музыки, сеть) — вне UI-потока; визуал и анимации — сильная сторона продукта, без подвисаний. Тема одна — тёмная «сцена» (`docs/spec.md`, 8а).

## Особенности API ИИ (легко забыть)
- Ключ — только в заголовке (`x-goog-api-key`, `Authorization: Bearer`), никогда в URL, логах, `AiException.detail`, трассировке и сохранённом JSON. `HttpAiProvider` дополнительно вырезает ключ из текстов ошибок; тесты это проверяют.
- Строгую JSON-схему на стороне провайдера не включаем — только «ответ — JSON»; 400 на JSON-режим или лимит токенов → один повтор без параметра.
- Google: только `streamGenerateContent?alt=sse` — без потока сервер рвёт соединение примерно через 240 с («Connection closed before full header was received»). Строгая схема — `responseJsonSchema` без `$schema`/`$id` (с `$id` — 400 «reference to undefined schema»). `thinkingLevel` — заглавными (LOW/MEDIUM/HIGH). Inline-запрос — до 20 МБ всего (base64 ×4/3), видео больше 14 МБ — File API (resumable upload → ждать `ACTIVE` → `fileData.fileUri`), файл удалять `DELETE` в любом исходе. «Размышление» gemini-3.8-flash не отключается (`minimal` → ошибка) и входит в `maxOutputTokens`. temperature/topP/topK для Gemini 3.6+ не передавать. `models.get` не сообщает модальности. Часто 503 «high demand».
- OpenRouter: ошибка может прийти в ответе 200 (`error` в теле); неподдерживаемые параметры молча игнорируются; `:free` — 20 запросов/мин и 50/день (тесты не гонять впустую). Видео — `video_url` с data URL; предел размера не документирован (у нас 20 МБ); **видео требует баланс от $1 даже на `:free`** (402). Nvidia-модели отклоняют запрос с ~20 изображениями (422 «content safety screening») — «Максимум кадров» в настройках.
- Anthropic (`anthropic-version: 2026-10-21`): ключ — `Authorization: Bearer`; temperature/top_p/top_k запрещены (400); нет JSON-режима без схемы, prefill ответа запрещён (400) — последнее сообщение всегда пользователя; `max_tokens` обязателен, у нас 16000 (без потока большой лимит рискует таймаутом); до 100 изображений у моделей с окном 200k.
- OpenAI: Responses API (`/responses`), `instructions`, `input_image`, `store: false`.
- FFmpeg без GPL: нет libx264. Облегчённая копия — `h264_mediacodec` (Android) / `h264_mf` (Windows), запасной `mpeg4`.
- Потолок анализа — `analysisTimeLimit` (5 мин) в `analysis_pipeline.dart`; повтор — только если хватает времени.
- Живые тесты (`integration_test/live_ai_test.dart`) — только по команде автора; ключи из `DANCEAI_GOOGLE_KEY`, `DANCEAI_OPENROUTER_KEY` (переменные пользователя Windows: читать из реестра в процесс теста, не выводить).

## Правила работы
- **Новые зависимости** (pub-пакеты, нативные библиотеки, инструменты) — сначала предложить автору: зачем, альтернативы, лицензия, поддержка Android и Windows. Добавлять после согласия.
- `docs/spec.md`, `assets/criteria.json`, `assets/report.schema.json`, `assets/prompts/` меняются только отдельной задачей. Нашёл ошибку — сообщи автору.
- Перед коммитом: `flutter analyze` и `flutter test` — зелёные.
- Не коммитить: `test_videos/`, `.env`, ключи и keystore (`*.jks`, `*.keystore`, `android/key.properties`), `build/`, `.dart_tool/`.
- Общение с автором — на русском.
- Телефон автора — личный. Можно: устанавливать сборки, читать логи (`adb logcat`), замерять память, копировать временные тестовые файлы (и удалять их). Нельзя без отдельного разрешения: нажимать по экрану (`adb shell input`), запускать или открывать другие приложения, менять системные настройки.
